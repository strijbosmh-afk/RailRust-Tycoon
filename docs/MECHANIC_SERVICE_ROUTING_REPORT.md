# Mechanic service routing — 0.57.0

The hired park mechanic now uses the same height-aware public-path graph as visitors. A dispatch requires an inspection-due, closed, stationary, empty ride; a valid park entry; a reachable public path at its ride exit; and a complete public route from entry to that exit. The lowest eligible ride ID wins. One mechanic handles one assignment at a time. Movement takes 30 authoritative ticks per public-path edge, including sloped edges with their actual shared-edge height. The mechanic services the ride only at the exit landing and then walks toward the entry. Public-path edits invalidate the existing graph; current and next path references are reconciled on removal. A missing entry or route leaves the mechanic waiting without a service shortcut. Wage timing and the ledger remain as in 0.56.0.

The moving-character mesh now draws an original teal uniform, safety cap and tool case at the path-based position. Its roof-clipped shadow and feet depth use the same physical rules as visitor bodies. The retained renderer builds one staff template and reuses it; the independent geometry oracle draws the same shape for verification. The Operations notice exposes idle, waiting and travelling states.

Strict park saves advance to **28/28** with a mechanic route object containing current and next public path IDs, partial edge progress and target ride ID. Schema 27 and older migrate to an idle route. Current saves require the field; older-schema smuggling, missing nested fields, invalid path references, disconnected next edges and impossible progress are rejected. No dependency, imported asset or random draw is added. The normal map, object and save-size caps remain unchanged.

The mechanic does not reserve path space or collide with guests. The direct manual Service ride action still works without a physical mechanic. Future stages can add handymen, visible litter and vomit, patrol zones, inspection duration and breakdown repair. This PC is excluded from performance acceptance. The cross-PC build, proof identities and local package are recorded in [RESUME_DEVELOPMENT.md](../RESUME_DEVELOPMENT.md).
