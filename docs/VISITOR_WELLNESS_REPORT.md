# Visitor wellness and Rest facilities — 0.51.0

This stage adds energy and nausea to authoritative guest state. Walking, waiting, completed coaster/carousel trips and natural recovery change them on the fixed simulation clock. Very tired or nauseous visitors defer new ride choices while current reservations and journeys retain their existing ownership. A buildable, priced Rest facility uses the ordinary public-path access, one-at-a-time service, supplies, upkeep, finance ledger, demolition and cancellation pipeline. Its completed use relieves both wellness values. Guest inspection and park-wide statistics show the new condition, and urgent triage includes both values.

The Rest pavilion is original procedural geometry in the existing one-tile service envelope. No external art, font, dependency or wellness-specific navigation random draw is added. All new state is bounded to 0–100. The save pair advances to **25/25** with explicit field-shape checks: older schemas cannot smuggle wellness fields or Rest records, and current saves must include both new values. Versions 1–24 retain their historical fields and receive energy 80 / nausea 0 for existing guests. New guests use a deterministic per-ID seed independent of navigation RNG. Existing primary and backup locations and the 8 MiB file cap remain unchanged.
