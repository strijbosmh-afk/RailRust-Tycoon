# Campaign awards stage — 0.70.0

## Implementation

The first original campaign sequence starts with Meadow Challenge and unlocks Boardwalk Sprint after a recorded win. The Guests → Scenarios pane shows earned awards and locked or unlocked Boardwalk status, and refuses a locked start without changing the park. A completed scenario is observed after simulation and after a park load. Its award is recorded once in a separate local campaign file, so progress crosses new parks and game restarts without adding nondeterministic profile state to the authoritative simulation. Older completed Boardwalk saves can grant their own award and retain access.

`campaign.json` has a strict format/version and bounded size. The game stages and flushes writes in the save directory, uses the existing save lock, rotates a previous valid record to `campaign.json.bak`, and attempts backup rollback if the final replacement fails. A damaged primary can be read from the backup. If both records fail validation or the primary has a future version, the game refuses campaign actions and keeps both files for recovery. This record lives next to, but is independent of, the strict **39/39** park save and backup. When moving PCs, both campaign files must be copied alongside the park files.

The `write-campaign` / `verify-campaign` proof checks a locked Boardwalk button, completes Meadow through the real simulation, writes its award and park save, then reopens in a separate process. It verifies the Meadow award and Boardwalk unlock, confirms a second observation does not rewrite the award, starts Boardwalk from its actual button in a new park, and keeps the winning primary save byte-identical. Windows CI runs the proof. Focused tests cover format refusal, backup recovery, idempotence and the button gate. The previous Boardwalk success/failure and Meadow continuation proofs remain in CI.
